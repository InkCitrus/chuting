# 实现说明

## 组成

- `music_calendar/store.py`：SQLite schema、候选合并、首次时间校验、原始响应归档、冲突、按月查询。
- `music_calendar/client.py`：串行 JSON-lines 请求通道，管理 Node 子进程与请求超时。
- `music_calendar/provider.cjs`：账号凭据只在内存使用，读取 macOS 官方客户端 Cookie 或 `NETEASE_COOKIE`。仅开放项目需要的只读模块。
- `music_calendar/sync.py`：候选发现、逐曲查询、请求间隔、暂停和失败恢复。
- `music_calendar/server.py`：本机 HTTP 服务，提供账号连接、采集控制、状态、月历、搜索和导出。
- `web/`：原生 HTML、CSS、JavaScript，访问同源 API，无外部字体或分析服务。

## 去重与冲突

候选主键为 `(uid, song_id)`，来源单独保留。首次播放事实同样按账号和歌曲唯一；观测记录按 `(uid, song_id, first_listen_ms)` 唯一。重复导入不新增事实或观测；不同首次时间保留为多个观测，保留最早采集的显示版本，不擅自取最小时间。

时间按 Unix 毫秒保存；按北京时间月份边界查询，避免 UTC 跨日归档错误。该接口出现秒级时间值、未来时间或不匹配的歌曲 ID 时拒绝导入。

## 暂停与续采

每首歌曲完成后提交状态。暂停等待当前请求返回；剩余歌曲保持待查询。重启时把上次未结束任务标为中断，再次采集跳过已有结果。失败歌曲在下一批重试，空结果需要显式选择重查。遇到登录失效、权限限制、风控或限流立即停止，连续三个查询错误也会停止。

命令行对数据目录持有进程文件锁，避免网页和独立 CLI 同时采集。一个任务内只处理每个候选一次，不会反复选择失败条目。

## 本机访问

服务绑定 `127.0.0.1`，检查 Host 和写请求 Origin，不返回跨域许可。状态修改要求 JSON 请求。Cookie 不进入 Python、HTTP 响应或原始数据档案；Node 不序列化可能带请求头的上游异常。数据库及原始响应权限为本机用户读写。

如未来提供远程访问，应增加身份验证、HTTPS 和每用户数据隔离，不能直接把当前服务绑定到公网。

## 已知边界

- 候选发现覆盖近期、累计排行、喜欢的歌曲及自己创建的歌单；尚未自动扫描历年月榜或订阅歌单，也不保证发现全部历史歌曲。
- 部分歌曲“回忆坐标”为空，需保留状态供后续补查。
- 首次收听是上游提供的事实，其记录规则不是本项目控制的。
- 上游依赖受网易接口和网络状态影响。核心测试独立于上游。
