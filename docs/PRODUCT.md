# 产品范围

## 核心体验

用户打开日历，能回答“这一天我听了哪些歌、是在几点几分”。月份切换保留筛选条件；点击日期打开当日歌曲列表；点击歌曲查看来源、首次收听时间和可用的累计统计。

首期以“首次播放日历”为主：按接口提供的首次收听时间归入当地日期，时间显示到分钟；日历和详情页均明确当前模式。真正的播放事件可在后续以独立模式接入。

## 数据要求

1. 保存歌曲 ID、歌名、歌手、首次收听原始时间戳、来源字段与采集时间。
2. 首期显示时区为 Asia/Shanghai；底层存储 Unix 时间戳，避免截断到分钟造成信息丢失。
3. UI 的 `HH:mm` 是格式化显示，不意味着服务端时间精度或事件语义已经完整验证。
4. 按账号与歌曲 ID 保存首次收听事实，重复采集不会生成重复的首次播放记录；保留时间冲突与来源，不能静默覆盖。
5. 后续播放事件按账号、歌曲 ID、来源时间戳去重，不能只按歌曲 ID 去重。
6. 接口空结果表示暂无可用数据，不等于从未播放；失败必须可重试。
7. 月榜、累计次数、周报和年度精选事件分别存储；不能把统计次数展开成伪造时间的播放记录。
8. 日历空白表示当前采集没有记录，不断言当天没有听歌。

## 候选歌曲来源

优先合并用户歌单、喜欢的歌曲、近期播放、听歌排行及已有周报中的歌曲 ID，再逐曲查询“回忆坐标”。这些来源的并集仍不保证覆盖账号曾听过的全部歌曲；界面需显示已发现歌曲数、已查询数、有效首次时间数与失败数。

## 首期验收

- 已取得首次收听时间的歌曲能出现在正确日期，列表时间显示到分钟。
- 重复采集保持日历条目数量稳定。
- 时区跨日、无日期、接口错误与来源冲突有明确处理。
- 可以查看数据来源与采集覆盖，导出原始时间戳。
- 明确区分首次播放与完整播放记录，不承诺无法验证的终身覆盖。

## 后续

可接入可靠的本地播放事件或既有日志，补充同一首歌的多次收听；日历按记录类型切换，保留每类数据的完整性说明。
