# 产品范围

## 它回答什么

打开日历，能看见「这一天我遇见了哪些歌、是几点几分」。换月份筛选还在；点开日子看当天的歌；再点一首，看它是哪天第一次响起、后来听了多少遍。

首期就是初听日历：按「回忆坐标」给的第一次时间，归到当地那一天，显示到分钟。同一首歌后来的每一遍，是以后的事。

## 数据怎么存

1. 留住歌曲 ID、歌名、歌手、初听原始时间戳、来源和采集时间。
2. 显示用 Asia/Shanghai；底层存 Unix 时间戳，不截到分钟。
3. 界面上的 `HH:mm` 只是显示格式。
4. 按账号和歌曲 ID 存初听事实，重复采集不会多出条目；不同时间都留着，不悄悄覆盖。
5. 以后的播放事件按账号、歌曲 ID、来源时间戳去重，不能只按歌曲 ID。
6. 接口空结果＝暂时没有，不等于从没听过；失败的可以再问。
7. 月榜、累计次数、周报、年度精选各自存；不把次数拆成假的播放记录。
8. 日历某天空着，只说明这次没采到，不说那天没听歌。

## 歌从哪儿来

喜欢的歌曲、近期播放、听歌排行、歌单和周报里的 ID 合在一起，再逐首问「回忆坐标」。网页默认只开喜欢的歌，其他来源在设置里。界面会显示已发现、已查询、找到初听、暂无记录和失败的数量。

## 首期验什么

- 有初听时间的歌出现在正确日期，列表显示到分钟。
- 重复采集，日历条目数不变。
- 跨日、没日期、接口出错、时间对不上，都有明确处理。
- 能看到来源和覆盖情况，能导出原始时间戳。

## 以后

接上可靠的本地播放事件或已有日志，同一首歌的多次收听就能补上；日历按记录类型切换。
